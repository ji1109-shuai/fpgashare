# 颜色分类与界面精简（2026-10-19）

## 已确认的起点

用户确认 `931b125` 自动白平衡版在现有背光板和照明下不再偏绿。`de7d754` 保存该现场确认，尚未包含本轮颜色修改。此前失败的固定单位增益、手动白纸/SW4 流程均未恢复。

本轮改动仍需用户自行 TD 构建、检查时序并上板验证；功能仿真不能代替实际颜色效果。

## 为什么改

原黄铜像素条件包含 `R<=2G` 和 `G>=B+G/4`，它们直接受亮度偏移和反光影响。例如人工样本 RGB=(180,84,24)，HSV 色相约 23°，旧规则输出 RED；这已在修改前的真实 RTL 仿真中复现。它说明旧分类边界存在问题，不代表已取得现场零件的真实 RGB。

原黑色规则排除最大通道低于 8 的像素，并对所有中性色使用 `max/8+4` 的通道差容差；整件还要求黑票达到有效票的 80%。极暗材料、轻微偏色和中性反光可能分别导致样本丢失或整件 UNKN。

## 当前算法

颜色输入仍是自动白平衡后的 RGB，与外形使用的二值像素严格对齐。每拍四像素，像素分类保持两拍；没有增加除法器、帧缓存或改变视频/DDR 连续性。

1. 暗中性像素：`V=max(R,G,B)`，`D=max-min`。若 `V<=5*reference/16` 且 `D<=V/4+4`，计为黑色；真正全零前景也提供黑色证据。零件版 reference 仍为原值 224，对应黑色上界 70。不是将未识别像素归黑。
2. 其余有效像素需 `16<=V<250`。若 `D<=V/8+4`，在 `V>=3*reference/8` 时计为银色；保留原银色亮度与中性条件，以及黑银之间的拒绝区。
3. 有彩色像素通过 HSV 色相区间判断：红色 -15°..15°（包含首尾环绕），黄铜 18.75°..67.5°。边界间隔及绿、蓝、紫等不支持颜色保留 UNKN。这里是黄色/暖黄色外观分类，不能通过色相确定金属材质。
4. 不计算完整 HSV 数值。利用 `H=60*(G-B)/D` 等分段关系，将固定色相范围化成移位、加减与交叉比较；运算先扩位再移位，避免溢出。参考 OpenCV 的 HSV 分色思想，未引入第三方 HDL。
5. 仍只统计原前景、优先采用零件内部单元。白色背板及孔洞不参与银色投票；内部样本不足时保留原回退。红/黄铜之间仍需两倍票差及至少 40% 有效色票；银色仍需 80%；黑色改为至少 60%。保留最低票数、覆盖率与跨帧确认。黑银各半或红黑各半不会因为规则顺序自动得到类别。

黑色判定中放宽的是暗部中性容差和反光容忍度；非常暗的低饱和彩色仍可能与黑色不可区分，不能声称对任意光照稳定。过曝且无色彩信息的像素不用于推断红/黄铜；HSV 不能恢复已丢失的色彩。

## 界面

生产顶层关闭 `COLOR_DIAGNOSTICS`、`WB_DIAGNOSTICS` 和显示模式文字。仅保留 EXP/GAIN 两行控制值、安路图标、已确认目标的框与颜色/形状标签。视频模式开关继续工作，自动白平衡继续运行，未增加白纸校准或锁定步骤。诊断代码保留，可在确有需要时通过参数重新启用。

## 功能验证与复测方法

- `tb_parts_color_hsv`：独立实数 HSV→RGB 样本生成器，534 组人工色相/亮度/饱和度、黑银边界和异常输入，另逐拍检查两拍延迟。
- `tb_parts_colours`：完整捕获、分割、内部取样、单元投票、形状及跨帧确认；新增暖黄铜、偏暖黑、全零黑、单元内部/单元之间分布的黑银反光和混色拒绝用例。
- `tb_parts_colour_stability`、`tb_parts_multi_no_calibration`：保留兼容模式、无手动门控和四目标关联检查。
- `tb_parts_clean_overlay`：逐输出像素检查图标、四目标标签、EXP/GAIN、删除无效目标；原 WB/RAW 及模式文字区域需恢复底图，不用文字移出画面来伪装删除。
- 自动白平衡与实际尺寸 ISP、Sobel/EDGE DDR 帧尾连续性用原回归核验。逐项结果另存 `COLOR_HSV_RESULTS_20261019.txt`。

用户下载本轮 bit 后先保持已经正常的灯光、EXP/GAIN 和摄像头高度。四种颜色分别单放，再同时放四件，观察标签；黄铜、黑色在背板中心与四周、几个平面旋转角度分别停留 2 秒。记录“真实颜色→标签”、位置、反光面积及 EXP/GAIN。无需重新白纸校准。若仍错分，应基于这一版现场数据细化，而不能仅据手机拍屏颜色当作相机原始 RGB。
