## 实际查阅的公开来源

OpenCV 文档站在本机返回 HTTP 403，本轮通过其官方 GitHub 仓库阅读了对应教程和源码；不是仅凭搜索摘要得出结论。

### 1. OpenCV HSV 与 inRange：分离色相、饱和度和亮度

- [官方教程源码](https://github.com/opencv/opencv/blob/43a4c20ef8c023a8e26aee50ccf7face4aa7c976/doc/tutorials/imgproc/threshold_inRange/threshold_inRange.markdown)
- [官方 RGB→HSV 实现](https://github.com/opencv/opencv/blob/43a4c20ef8c023a8e26aee50ccf7face4aa7c976/modules/imgproc/src/color_hsv.simd.hpp)

教程说明 H 用于颜色类型，S 区分有彩色与灰色程度，V 表示明亮程度；仅靠三个 RGB 分量直接划分对象更难组织边界。源码对 8 位输入采用最大/最小通道、差值、倒数表和整数运算实现转换。

可借鉴的框架：先判断该像素是否有可用的亮度和色彩信息，再分别处理有彩色与无彩色。红色和黄铜色比较 H 分布并限制 S 的可信范围；很暗的像素不应依赖 H 稳定，也不应要求 R、G、B 极其接近才允许进入黑色候选。

限制：HSV 不是照明不变颜色，也没有内置“金属黄铜”和“银色”物性识别。红色在 H 的首尾两端都有范围，需要环绕处理。OpenCV 普通 8 位 HSV 的 H 通常为 0..179，而角度是 0..360；浮点和 FULL 格式又不同，实现时必须明确约定。

### 2. OpenCV 颜色校正模型：白平衡不等于完整颜色标定

- [官方 Color Correction Model 教程](https://github.com/opencv/opencv_contrib/blob/6484ab27bd332762f36262bf3b3f743720f4ca1b/modules/mcc/tutorials/basic_ccm/color_correction_model.markdown)

教程使用色卡的多个已知色块与相机测量值估计颜色校正矩阵，支持明确参考色空间，也允许自定义参考色值。它与只用一张白纸调 R/B 增益不同：中性白正确，不能保证红色和黄铜的色相都正确。

本项目可先用实际四类零件建立分类样本分布，不必立即要求购买专业色卡。它属于针对样品的分类标定，不能被称为标准色度标定或真实材质色测量。若以后需要更准确的跨设备颜色一致性，再考虑带已知参考值的多色标定。

### 3. OpenCV 白平衡文档：不同任务需要不同的样本筛选

- [官方白平衡接口说明](https://github.com/opencv/opencv_contrib/blob/6484ab27bd332762f36262bf3b3f743720f4ca1b/modules/xphoto/include/opencv2/xphoto/white_balance.hpp)

文档包含饱和度筛选、过曝像素筛选以及不同白平衡方法。它说明样本适用性应明确处理，但不能据此把所有低 S 像素都删掉：银色本来就可能低 S，黑色本来就暗。白平衡样本筛选与物体颜色分类的筛选规则不能照搬。

固定平台仍建议完成白平衡后锁定，不因为画面中出现多个有色物体就重新进行全局灰度世界校正，避免场景颜色比例变化引起补偿漂移。这是本项目的工程选择，不是教程保证本项目一定稳定。

### 4. FPGA RGB→HSV 公开实例：只参考架构，不直接复制

- [tonyre4/RGBtoHSV_FPGA_core](https://github.com/tonyre4/RGBtoHSV_FPGA_core)
- [已查看的 VHDL 转换源文件](https://github.com/tonyre4/RGBtoHSV_FPGA_core/blob/2d03dc600ad60fecd089b87c0badd47d2183f784/rgbtohsv.vhdl)

该文件实现最大/最小通道、差值和多个 divider 实例，说明 FPGA 实现 HSV 有公开参考。该小型仓库不等同于成熟工业产品，不证明它的数值、吞吐、时序、许可证或本板资源预算已符合要求。本轮没有引入其代码。

本项目每拍四像素、已有时序裕量较小，不应原样复制多路组合除法。若采用 HSV，可评估流水化倒数 LUT，或对固定 H/S 区间使用无除法的交叉乘法比较。新增延迟必须同时对齐像素、有效和帧行标记，并做数值边界及实际尺寸回归；资源、时序最后由用户 TD 构建结果确认。

## 建议替代路线及边界

1. 保留当前能用的白平衡锁定、形状识别和显示通路。把颜色分类视为单独任务，不把 `REF:OK` 当成分类一定正确。
2. 采集实际零件表面像素的分布。先固定一组曝光、增益、锁定状态和灯光，对黑、银、红、黄铜各采集多个位置和角度；记录每个位置为独立样本。不要用一两个理想 RGB 常量代表整类材料。
3. 有彩色路使用 H/S 分布；暗像素路使用可用的亮度与噪声范围；银色路使用中等可用亮度和低色度证据，并区分白色反光比例。最暗像素、过曝像素和无彩像素不能用一个统一拒绝规则处理。
4. 用按类别归一化的样本分布/直方图或者小型原型距离模型汇总目标，保留相近类别的拒绝间隔。不要继续依靠“暖色优先”来掩盖像素类别定义相交。中值/截尾统计可降低异常点影响，但具体估计量必须用实际样本比较；不能预先保证某一种总是更好。
5. 使用另一些位置/角度作为验证集，检查黑/银与红/黄铜的混淆矩阵；同一帧内像素随机切分不能代替独立拍摄验证。PC 上实测验证有效后，再做定点化和 HDL 对照。

暂不采用“换成 HSV 就能自动消除光照影响”“低饱和高亮全都丢弃”“颜色未知就当黑色”等规则。金属反光可能带光源或周围物体的颜色，通道裁剪会丢失信息，去噪不能凭空恢复真实颜色。

## 下一步需要的数据

最小排查：同一曝光/增益和锁定状态下，单独放黄铜件和黑色件，分别记录屏幕 `RGB`、`WHY`、`WB/REF`。详细诊断主要对应第一个目标，所以先单独放置。

现有 `RGB` 是前景的稀疏均值，仅可初步判断亮度、色偏或门控问题，**不能代替表面像素的 H/S/V 分布**。如果仍只有均值，下一步应优先提供目标颜色分布/样本导出诊断，再做分类拟合。不要让用户反复烧录只改变门限的版本。

手机拍显示屏的照片可用于观察标签、反光位置和读取诊断文字；手机白平衡与屏幕显示会改变颜色，不能从照片直接提取 RGB 充当相机输出真值。

本轮代码边界核验没有更改生产 RTL；后续替代分类器尚未实现和验证。当前实验版本保留以供追溯，不作为颜色稳定版本提交/发布。
