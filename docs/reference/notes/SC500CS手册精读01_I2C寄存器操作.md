# SC500CS 手册精读 01：怎么操作摄像头寄存器（I2C 全解）

> 手册依据：§1.5 配置接口（p13-14，图 1-10、表 1-4/1-5）
> 代码依据：`uicfgcs500.v`（调度层）、`uii2c.v`（波形层）、`uics500reg.v`（寄存器表）

---

## 1. 摄像头的三条控制通道（I2C 只是其中之一）

| 通道 | 板上引脚 | 作用 |
|---|---|---|
| **I2C**（SCL=K3, SDA=J3） | 寄存器读写 | **一切行为的开关**：分辨率、曝光、增益、MIPI格式、测试模式…全靠写寄存器 |
| EXTCLK = 24M 时钟（L3） | 给传感器 PLL 提供参考 | 没有它芯片不工作 |
| PWDNB 复位（L2） | 上电时序控制 | 手册 §1.4：拉低=复位/休眠 |

MIPI 是单向的（传感器→FPGA 的图像数据），**I2C 是唯一的控制通道**。

## 2. 物理层：两根线，谁拉低谁说话

- SCL：时钟，本设计由 FPGA（主机）驱动；
- SDA：数据，**开漏(open-drain)双向**——任何一方都只能"拉低"，释放时靠上拉电阻回高（手册图 1-3 里的 4.7kΩ，板子约束里两个脚都配了 PULLUP）；
- "线与"逻辑：想发 1 就放手，想发 0 就拉住。

## 3. 地址：摄像头为什么叫 0x6C

手册表 1-4：7 位设备地址由 **SID 引脚电平**决定——接地 = **7'h36**（内置下拉，默认如此）。
I2C 报文里地址占 8 位 = 7 位地址 + 1 位读写方向：

```
7'h36 = 100_0110... 等等：0x36 = 011_0110
左移一位补写位0：0110_1100 = 8'h6C  ← 代码里 CAM_ID = 8'h6C 的来源
读操作则是 0x6D（末位=1）
```

## 4. 一次写寄存器的完整报文（手册图 1-10 逐字节走一遍）

以"把窗口宽度寄存器 0x3208 写成 0x04"为例（对应配置表条目 `{16'h3208, 8'h04}`）：

```
[S] 起始：SCL高时SDA由高变低
[0x6C] 设备地址+写位     → 第9拍摄像头拉低SDA = ACK应答
[0x32] 寄存器地址高8位   → ACK
[0x08] 寄存器地址低8位   → ACK
[0x04] 数据              → ACK
[P] 停止：SCL高时SDA由低变高
```

**关键特点：SC500CS 的寄存器地址是 16 位、两个字节**（很多简单传感器只有 8 位地址）。这也是为什么代码里 `I_wr_cnt = 4`（设备地址+地址高+地址低+数据，正好 4 字节，`WMEN_LEN(4)`）。

**ACK 的调试价值**：第 9 拍 SDA 没被拉低（NACK）= 摄像头没挂上总线——排线没插好、地址错、或没供电。这是 I2C 调试的第一判据。

## 5. FPGA 侧的三层代码架构

```
uics500reg.v      【剧本层】  122条 {16位地址, 8位数据} 的配置表 + uics500regAE 5条AE表
      │ 逐条索引 REG_INDEX
      ▼
uicfgcs500.v      【调度层】  状态机：取一条表项 → 打包成4字节 → 发请求 → 等忙结束 → 下一条
      │ I_iic_req / I_wr_data{ID,AddrH,AddrL,Data}
      ▼
uii2c.v           【波形层】  按CLK_DIV分频产生SCL，把字节变成SDA上的波形，
                              处理起始/停止/移位/采样ACK，忙了置O_iic_busy
```

**SCL 频率怎么来的**：`CLK_DIV = 24000000/100000 - 1 = 239`，24MHz 时钟分频出 **100kHz** SCL——正好是手册表 1-5 Standard-mode 的上限（Fast-mode 可到 400kHz，想快可以改）。

**两个 done 标志的时序**（uicfgcs500 状态机）：
- 主表 122 条写完 → `O_cfg_done=1`；
- 接着自动切换到 AE 表写 5 条（REG_DATA 多路选择器翻转）→ `O_ae_cfg_done=1`；
- 两 flag 都为 1 后，`ae_set` 才允许发 AE 更新请求。

## 6. 运行中改寄存器：唯一开放的通道是 AE 表

上电后主表只写一次。运行时想改摄像头行为，现有机制只支持：按按键 → `ae_set` 改曝光/增益值 → `r_ae_req` 脉冲 → 调度层 `reg_index` 归零、重写 **AE 那 5 条**（0x3e00/01/02 曝光 + 0x3e08/09 增益）。

想运行时改别的寄存器（比如测试模式），就要照葫芦画瓢：扩充 AE 表或仿照写第二张运行表。注意手册 §2.3 GROUP HOLD：多条寄存器要"同时生效"时应该用打包机制，否则改一半的参数集会撕裂画面。

## 7. 读寄存器：本工程没用，但调试必备

手册图 1-10 的读格式（注意中间的重复起始 Sr）：

```
S → 0x6C(W) → A → AddrH → A → AddrL → A → Sr → 0x6D(R) → A → data → NACK → P
```

`uii2c.v` 其实预留了读能力（`RMEN_LEN(1)`，一次读 1 字节），但顶层 `I_rd_cnt=0` 没启用。
**建议的调试实验**：上电先读 0x3107/0x3108（手册表 1-6，Sensor ID = 0xEE / 0x27），读到了说明 I2C 通路和摄像头全活着，比盲写 122 条寄存器再猜为什么没图要高效得多。
