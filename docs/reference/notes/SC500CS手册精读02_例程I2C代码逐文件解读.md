## 一、uii2c.v —— 波形层（262 行，I2C 主机控制器）

### 1.1 开漏总线的 Verilog 一行诗（第 92 行）

```verilog
assign IO_iic_sda = (sda_o == 1'b0) ? 1'b0 : 1'bz;
```

上一讲"谁拉低谁说话"的全部物理层，就是这一行：发 0 就驱动低电平，发 1 就输出**高阻 z**——线被上拉电阻抬回高电平。这就是开漏总线在 FPGA 里的标准写法（注释里的 Xilinx IOBUF 写法被弃用了，原理相同）。

### 1.2 SCL 怎么产生（第 72-74、110-120 行）

```verilog
localparam SCL_DIV = CLK_DIV/2;              // 239/2=120
// clkdiv 数到 120 翻转一次 scl_clk → 24MHz / (2×120) = 100kHz
assign scl_offset = (clkdiv == OFFSET);      // OFFSET = SCL_DIV - SCL_DIV/4
always @(posedge I_clk) O_iic_scl <= scl_offset ? scl_r : O_iic_scl;
```

**OFFSET 是本文件的精华**：数据（SDA）在内部时钟 `scl_clk` 的上升沿更新，而外部真正的 SCL 边沿被刻意**延后 3/4 个半周期**才输出。效果：SDA 每次变化都发生在 SCL 依然为低的时候——这就是手册表 1-5 里 tSU;DAT（数据建立时间）在硅片上的实现方式。**数据变化时钟沿和数据采样时钟沿错开**，是所有同步接口驱动的通用手法。

### 1.3 八状态机：把上一讲的报文图翻译成代码（第 63-70、188-260 行）

```
IDLE  ──req──▶ START ──▶ W_WAIT ──▶ W_ACK ──┬─没写完──▶ W_WAIT（下一字节）
 全松手      SDA拉低    移位发8bit     第9拍      ├─还有读───▶ IDLE（rd_req=1→重复起始Sr）
             产生起始位  （发完进ACK）  查ACK     └─全部完成─▶ STOP1 → STOP2 → IDLE
```

逐个状态对照报文：
- **START**：组合逻辑把 `sda_o` 拉低（第 134-139 行），配合 scl_offset 延迟的 SCL 高电平 → 产生"SCL 高时 SDA 下跳"的起始条件；
- **W_WAIT**：发送移位寄存器 `sda_r <= {sda_r[6:0],1'b1}` —— **高位在前（MSB first）**，8 拍发完一个字节；字节来源 `sda_r <= I_wr_data[(wcnt*8) +: 8]`，按字节序号从 32 位打包寄存器里抽取；
- **W_ACK**：sda_o 释放总线（高阻），第 9 拍采样 `sda_i`；
- **STOP1/STOP2**：先 sda=0/scl=1，再 sda=1/scl=1 —— "SCL 高时 SDA 上跳"的停止条件，两个状态就是为了按顺序摆出这两拍。

### 1.4 ACK 检测：写了错误标志，但没人接！（第 176-185 行）

```verilog
if(IIC_S == W_ACK && sda_i == 1'b1)   // 应答拍 SDA 还是高 = 从机没应答
    O_iic_bus_error <= 1'b1;
```

版本 1.1 特意升级了这个 NACK 检测（文件头注释还写了"可以通过观察 O_iic_bus_error 查看总线是否有错误"）——**但 uicfgcs500 例化时根本没连这个端口**！又一个"作者留了没人用"。想调试 I2C 的话，把它接出来就是现成的错误指示灯。

### 1.5 读操作：完整实现，只是没启用（第 133-139、224-231 行）

写完设备地址后若 `I_rd_cnt>0` 且随机读模式，状态机**回到 IDLE 并置 rd_req=1**——再次进 START 就会发 `{7'h36,1'b1}=0x6D`，这正是手册图 1-10 的重复起始 **Sr** 格式。接收侧在 `negedge scl_clk`（SCL 下降沿，数据最稳的时刻）移位采样。读 Sensor ID 的硬件基础已备好，只差上层调度用它。

## 二、uics500reg.v —— 剧本层（121 条的"开机脚本"）

```verilog
assign REG_SIZE = 120 + 1;                 // 121 条（之前我说122，更正：121）
case (REG_INDEX)
    0:   {16'h0103, 8'h01}   // 软复位（手册表1-3，复位持续150ns）
    1:   {16'h0100, 8'h00}   // 待机：配置期间先别出图
    ...  // 2~119：真正的配置（PLL、MIPI、窗口、时序、增益……）
    118: {16'h3e08, 8'h08}   // 增益初值
    119: {16'h3e09, 8'h5f}
    120: {16'h0100, 8'h01}   // ★最后一条：流开启！开始出图
```

**教科书式三段结构：复位 → 待机中配置 → 最后一条开机**。这就是手册 §1.4/表 1-2/1-3 的寄存器在真实工程里的用法。之前讲的"上电先亮后暗"，第一段参数就写在 118/119 条。

**两个进阶观察**：
1. 条目 2/3 写 `0x36e9=0x80、0x36f9=0x80`，条目 17/18 又改回 `0x04`——这对寄存器是厂商的"寄存器组解锁密钥"，**公开数据手册里查不到**（手册只公开了子集）。读代码时遇到手册没记载的寄存器很正常，别慌，那是 FAE 给的 magic。
2. 条目 22~29（0x3200~0x3207）是时序窗口坐标，手册表 2-8 只覆盖了 0x3208 之后的输出窗口——同样是"手册公开子集"的例子。

## 三、uicfgcs500.v —— 调度层（握手协议）

三层之间的接口只有四个信号，本质是一个**请求-忙握手**：

```
剧本层 ──REG_DATA/REG_SIZE──▶ 调度层 ──I_wr_data{ID,AddrH,AddrL,D}, I_iic_req──▶ 波形层
       ◀────── REG_INDEX ─────       ◀──────────── O_iic_busy ────────────
```

调度层状态机（TS_S 0→1→2→3 循环）：
- 状态 1：`!iic_busy` 才打包发送 —— **等上一笔事务结束**；
- 状态 2：等 busy 拉高（请求被接收）→ 撤掉 req；
- 状态 3：等 busy 拉低（整笔事务含 STOP 完成）→ `reg_index+1` 取下一条；
- 全部写完 → 置 `O_cfg_done`；随后多路选择器切到 AE 表，再写 5 条 → `O_ae_cfg_done`。

这个"req→busy→done"三段握手是所有外设控制器驱动的通用模板，值得背下来。
