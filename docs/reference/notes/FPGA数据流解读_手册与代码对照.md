## 〇、先看三个重要更正（比原来版本更准确的真相）

### 更正 1：裁剪发生在传感器内部，不在 FPGA
配置表 `uics500reg.v` 第 30~41 行写了输出窗口寄存器（手册表 2-8）：

| 寄存器 | 代码写入值 | 含义（手册表 2-8） |
|---|---|---|
| 0x3208/09 | 0x0400 | 窗口宽度 = **1024** |
| 0x320a/0b | 0x0258 | 窗口高度 = **600** |
| 0x3210/11 | 0x0004 | 列起始 = 4 |
| 0x3212/13 | 0x0004 | 行起始 = 4 |

即：**传感器只读出 2600×1952 阵列左上角起 1024×600 的窗口**（起点 (4,4) 是为了跳过手册图 2-3 标注的 4 行/4 列 Active Border）。MIPI 总线上从头到尾只有这 1024×600 的数据。
**所以"成像太大"的根源是：视野只有传感器面积的 ~40%×31%。** 想扩视野 → 改这几个寄存器（配合 FPGA 侧 demosaic/VTC/DDR 的尺寸参数一起改）。

### 更正 2：`video_cuttting.v` 是死代码
全工程 grep 确认：`video_cutting` 模块**没有在任何地方被例化**（和 BLC.v 一样是作者留的旧版本/备用件）。我之前说"FPGA 里它负责裁剪"是错的——裁剪就是上面那组传感器寄存器干的。

### 更正 3：曝光上限的真正来源是 VTS=1127
配置表 0x320e/0f = 0x0467 → **帧长 VTS = 1127 行**（不是手册默认的 2000）。
手册表 2-2：最大曝光 = 2×VTS−10 = **2244 个半行**。`ae_set.v` 里 2246 的上限正是照着这个设计的（差 2，作者手滑）。
主配置表初始曝光 0x8C6 = 2246 半行 ≈ 顶格 → **曝光确实没有余量**，之前"暗"的分析里"曝光顶格"这条成立，但依据是 VTS=1127，不是帧长的 99.5%。

## 一、传感器输出"契约"（手册侧：FPGA 将收到什么）

### 1.1 物理层（手册 §1.7.1、图 1-11）
- **2 对数据差分线（MD0P/N、MD1P/N）+ 1 对时钟差分线（MCP/MCN）**，推荐速率 ≤1.0 Gbps/lane；
- 时钟线是** DDR**：数据在时钟双沿采样；本设计实际速率很低（1024×600×30fps×10bit ≈ 184Mbps 载荷，每 lane 约 100Mbps，远未跑满）；
- FPGA 侧用 **PH1P35 内置的 MIPI DPHY 硬核**接收（加密 IP `mipi_dphy_rx`），这是选这颗 FPGA 的原因之一（手册首页：MIPI DPHY：2）。

### 1.2 数据格式（手册表 1-9 寄存器 ↔ 代码配置）
| 寄存器 | 代码写入 | 含义 |
|---|---|---|
| 0x3018 = 0x3a | bits[7:5]=001 | **2-lane 模式** |
| 0x3031 = 0x0a | bits[4:0]=0xa | **RAW10 模式**（5'h8 则是 RAW8） |
| 0x3037 | （默认0x60） | PHY 接口 8bit 模式 |

### 1.3 像素怎么打包上总线（手册图 1-13/1-14 + RAW10 规则）
MIPI CSI-2 的字节流规则：
- **长包** = 包头(DI + WC低 + WC高 + ECC) + 载荷 + 包尾(CRC16)；
- **DI 字节** = VC[7:6] + DT[5:0]，DT 含义（手册表 1-8，也是 `csi_unpacket_2lane.v` 开头注释照抄的内容）：
  `00`=帧起始短包、`01`=帧结束短包、`02/03`=行起/行止、`2a`=RAW8 长包、**`2b`=RAW10 长包**；
- **RAW10 载荷排列**：4 像素 = 5 字节 —— 前 4 字节分别是 P0~P3 的高 8 位，第 5 字节是 4 个像素的低 2 位拼包 `{P3[1:0],P2[1:0],P1[1:0],P0[1:0]}`；
- **2-lane 交错**：字节按奇偶分到两条 lane（Byte0→lane0，Byte1→lane1…，手册图 1-14），接收端合并还原。

### 1.4 颜色排列（手册图 2-4 ↔ demosaic 参数）
首像素 (0,0) 是 **Gb**，阵列排布 `Gb B / R Gr` —— 即 **BGGR**，正是 `isp_top.v` 里 `demosaic #(.BAYER_MODE("BGGR"))` 的参数来源。

## 二、FPGA 逐级"吃流"实录（代码侧：位宽与功能）

```
SC500CS (RAW10, 2-lane)
   │ MIPI 差分对 ×3
   ▼
① mipi_dphy_rx（加密IP，芯片MIPI硬核）
   解串、时钟恢复、LP/HS状态检测、字节对齐
   → 输出 16bit/拍（= 2 lane × 1 byte，注释"2LANE，1BYTE模式"）
   ▼
② csi_unpacket_2lane.v（手写，138行，协议层剥壳）
   • 用 valid 的上升沿(S_head_en)识别包头
   • 读包头第 1 字节 DT：0x00→产生 frame_start 脉冲；0x01→frame_end
   • DT=0x2B → 读 WC（两个字节的16位拼出）>>1 得载荷字数，
     用计数器 S_data_en_cnt 门控出纯载荷
   • 每 2 个 16bit 拼成 1 个 32bit 输出（csi_valid_r 隔拍翻转，
     O_csi_valid 输出速率 = 输入一半）
   → 输出 32bit/拍（4字节），包头/ECC/CRC 已全部剥掉
   ▼
③ raw10_unpacket_2lane.v（手写，本工程最精彩的位操作）
   按 5 拍一个周期（S_cnt 0~4）重组字节流：
   • RAW10 的 4像素=5字节 导致字节相位以 5 为周期循环，
     代码用 S_csi_data_1d/2d 两拍延迟寄存器把"上一拍的像素高8位"
     和"这一拍的低位拼包字节"对齐（case 0~3 每拍拼出 4 像素，
     第 5 拍歇一口气——20 字节进来，16 像素出去）
   • 例（S_cnt=0）：P0 = {S_csi_data_2d[31:24], I_csi_data[25:24]}
     高 8 位来自延迟拍的字节0，低 2 位来自当前拍 LSB 字节的 [25:24]
     ——与手册 RAW10 排列逐位吻合
   • 最后 output 重排像素顺序（P3P2P1P0→P0P1P2P3）
   → 输出 40bit/拍 = 4 像素 × 10bit
   ▼
④ uial2axis（40bit 原生流 → AXI4-Stream 封装）
   补上 tvalid/tuser(帧起始)/tlast(行尾)，IMG 1024×600
   ▼
⑤ isp_top：demosaic(BGGR, 3×3窗口+行缓存, 双线性插值)
   40bit → 128bit (4×RGB888) → data128_96 → 96bit
   → AWB（逐帧统计+Q16定点除法器×8+50拍延迟对齐）
   → 96bit → data_96bit_to_128bit → 128bit
   ▼
⑥ video_in → DDR2(128bit 用户口) → video_out   【跨时钟域帧缓存】
   ▼
⑦ uivtc(1024×600时序) → hdmi_mixer → hdmi_tx(加密IP,TMDS编码) → 显示器
```

**位宽变化的主线**：16 → 32 → 40 → 128 → 96 → 128，每一级变化都有理由（剥协议开销 / 拼像素 / 转 RGB / 凑 DDR 总线位宽）。

## 四、这份手册给你的四个开发工具

1. **灰度渐变测试模式（表 2-10）**：往配置表加一条 `{16'h4501, 8'hbc}`（bit3=1），摄像头输出标准灰度渐变条纹——**不依赖镜头和光照就能验证整条 FPGA 链路**。画面条纹正常=链路通，问题在光路/曝光；条纹异常=数据通路有毛病。强烈建议作为你改代码后的第一个验证步骤。
2. **Sensor ID（表 1-6）**：调试 I2C 时先读 0x3107/08，读到 0xEE27 说明配置通路正常。
3. **扩视野路径（表 2-8 + 表 1-7）**：窗口寄存器最大可配到全幅 2592×1944；手册表 1-7 还表明传感器原生支持 **1280×720@60fps（2×2 binning）** 模式。你的 720p 升级正确姿势：**传感器窗口改 1280×720（居中：列起始 660、行起始 616）→ FPGA 侧 demosaic/VTC/DDR 尺寸同步改 1280×720**，比原来"只改显示侧"的方案视野大得多且数据量更小。
4. **GROUP HOLD（§2.3）**：把一组寄存器打包在同一场生效，避免改曝光/增益时画面撕裂——将来做 AEC 必用。

## 五、一句话总结

> **传感器按你配的窗口（1024×600@左上角）出 RAW10 图像，用 2 条差分线以 CSI-2 长包流式吐出；FPGA 用硬核 PHY 恢复成 16bit 字节流，手写两级解包剥掉协议外壳、把 5 字节/4 像素的紧排 RAW10 摊平成 40bit 像素流，交给 ISP 上色，再经 DDR 帧缓存换节奏，最后用 TMDS 编码送显示器。** 手册的表 1-8/2-2/2-8/2-10 就是这条链路的四张"接口图纸"。
