## 工程与问题

本次修改仅针对 `D:/fpgashare/fpgashare (4)/fpgashare`，入口是该副本的 `td_project/camera_to_dsi_display.al`。用户反馈前一版仍需手调后，重新核对了像素来源、默认开关、自动调节条件、传感器编码、I2C 应答和图像生效延迟。

前一版 `ae_once_lock_20261101` 有实际设计缺陷，不能作为本轮交付：

- 上电仍为 MAN，自动曝光没有默认运行；非零电机档位、已确认目标和小于16的亮度还会阻断自动调节。
- AE 使用 AWB 诊断包里的中心64×64原始绿色均值，中心有暗零件时不适合作为背景曝光依据，也没有独立的完整帧有效标志。
- 近目标时固定32曝光码的步长对短曝光过大，可能在目标两侧反复调整。
- 相机配置器忽略 I2C NACK，完成标志不能证明每个寄存器获得应答。这是源码审计发现的问题，尚无证据说它就是现场失败的唯一原因。
- 原AE测试注入亮度并模拟配置完成，没有覆盖开机默认菜单、真实图像测光和实际总线写入的闭环；不能据此证明开机自动曝光可用。

## 现在的完整链路

`CSI RAW10 → 原生产去马赛克 → AWB前RGB → 独立测光 → 跨域发布 → ae_set → 增益ROM → 曝光寄存器序列 → 真实uii2c → 摄像头`。

新增测光器在 `isp/isp_top.v` 内并联观察，RGB、有效信号、帧头、行尾、AWB和DDR路径没有插入新延迟。canonical RGB包首像素为最高24位；亮度为 `(R+2G+B)/4`。除去四边各1/16，每8×8格抽样一个像素，用16档直方图的75百分位作为背景亮度。这样小块中心暗零件不会独占测光；它仍是空间亮度统计，不是语义背景分割，不保证背景占比很小、强反光或任意光照下都合适。

测光独立检查完整1280×720帧、320拍每行、正确行尾及样本数。黑帧和饱和帧都是有效测量；半帧、异常行尾和不完整数据不能用于调整或证明收敛。支持上游多拍提前帧头。

相机配置器现在逐寄存器锁存总线错误，发生NACK时重写当前寄存器，只有获得应答才前进。摄像头持续不应答时保持配置未完成，AE不能伪报完成或LOCK；未增加新的硬件故障显示或寄存器读回，ACK也不等同于实物光学效果已确认。

传感器依据为工程内 `docs/reference/hardware/SC500CS_数据手册_V1.8.pdf`：第22页调节顺序、第23页曝光与增益寄存器/生效时序、第24～25页模拟增益表。写入第N帧，参数在N+2帧生效。曝光以半行为单位，最小码3；当前表VTS=0x0467=1127，最大码 `2*1127-10=2244`。不是微秒。3e03低四位为0xb，模拟增益写入3e08/3e09。

## 操作和控制行为

1. 复位后直接 AUTO，不需要先按键或手动调 EXP/GAIN。电机档位及识别结果不再决定是否允许曝光收敛。
2. 连续4个完整有效观测在176～216目标区间同一侧，才产生一次调整；远暗时曝光每次最多增加约50%，避免“翻倍饱和→减半偏暗”的往返振荡；近处曝光步长为当前曝光约1/16且不超过32码，最少1码。
3. 每次实际I2C参数写完后丢弃2个完整测光包，再判断新的亮度；连续8包在区间内则菜单显示 `AE:LOCK`。
4. LOCK后即停止自动修改EXP/GAIN，亮度变化、物体经过和传送带启停都不会重新调节。
5. 需要重新适应灯光时，在菜单AE行选择MAN，再切回AUTO；复位也会重新启动。菜单EXP/GAIN编辑，或菜单外显式按相机KEY1/KEY2，都会接管为MAN。

到达曝光/增益边界仍达不到目标时保持AUTO，不宣称LOCK，也不重复写相同参数。自动白平衡继续按自身规则运行；AE锁定不同时冻结白平衡。
