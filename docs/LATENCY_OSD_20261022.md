# 识别批次延迟显示（2026-10-22）

右上角 `DET:123.4ms` 表示最近一次完整识别批次用时。上电等待、采集错误、超量程或超过约1秒没有结果更新时显示 `DET:---.-ms`。空场景也能发布一次完整分析结果，因此没有目标时出现延迟数字是正常的，不代表识别成功。

## 计时范围

- 起点：`img_tire` 实际接受某帧的首个有效输入拍，即 `capture_valid && capture_user && take`。忙时跳过的输入帧不重启计时。
- 终点：这批数据分析结束并发布全部目标的那个时钟沿。多目标模式为 `MULTI_PUBLISH`，单目标为最终发布状态14。
- 包含：首拍至帧采集完成、粗网格闭运算、白板搜索、连通域/孔洞与特征分析、各目标分类及这次批次结果发布。
- 不包含：传感器曝光/读出前段、起点之前的ISP流水、等待下一次被接受帧的时间、跨多次观测的类别确认等待、结果跨域后等候OSD帧边界、DDR缓冲、屏幕扫描与面板响应。

这是同一批输入至结果发布的内部延迟，不能称为摄像头拍到物体到屏幕显示的完整延迟。两路独立帧头相位差不能替代对应帧计时。将来若测视频端到端延迟，需要让帧ID/时间戳与实际DDR帧缓冲对应，或用外部光学方法测量。

## 实现

`recognition_latency_meter` 位于现有 `img_proj.v` 内，旁路读取接受/发布/错误事件，不控制视频通路。每11251个相机域时钟增加0.1ms，以四位BCD计数；无需除法器、乘法器或新帧缓存。按现有时钟报告112.511MHz换算，显示向下截断，量化误差小于0.1ms；这里只是数字计时精度，不是整个系统延迟的测量精度。

正常范围为000.0～999.9ms，达到1000.0ms失效，避免回卷成很小的假值。采集错误使该批结果失效；后续正常批次可恢复。

BCD数值、有效位和翻转事件通过 `isp_top`、顶层连接到 `hdmi_mixer`。源端保持整个数据包直到下次批次发布；事件经两级同步后采样该数据包，显示端仅在 `I_video_user` 更新，所以单个显示帧内数字不撕裂。显示端约1秒无更新则在下一显示帧标为失效。相机时钟停止时也可使旧读数失效；显示时钟本身停止时无法刷新画面。

OSD位于 x=1088..1263、y=16..31（1280×720），白字、深灰底，右侧留16像素。复用原OSD流水级，不增加视频延迟。该区域内文字优先于目标标签；目标框和标签在其他区域保留，安路图标与EXP/GAIN保留。临时颜色诊断也保留，待下一次颜色验证后关闭。

使能参数：顶层同时打开ISP与mixer的 `LATENCY_DIAGNOSTICS`。子模块默认关闭，方便复用。若实际时钟变更，应核对 `img_tire.LATENCY_TICK_CYCLES`（当前11251）及 `hdmi_mixer.LATENCY_DISPLAY_TICK_CYCLES`（当前7500，只影响旧数据超时）。

上板验收：

1. RGB模式等待启动，右上角应从横线变为毫秒读数；无需额外按键。
2. 分别空板、单件和多件，拍摄全屏或记录延迟范围。不同场景分析次数/区域不同，读数可能变化。
