# 偏绿排查与无效白平衡修复

本轮依据：上板照片显示 `EXP:2244`、`GAIN:112`、`WB:LOCK REF:BAD`，三件物体的形状框可见，颜色均为 `UNKN`。用户尚未用中性参考完成校准，并反馈降低曝光／增益会因孔内阴影影响形状。

## 已知结论

1. `LOCK REF:BAD` 说明当前没有有效的锁定参考，颜色识别按设计被禁止；此时 UNKN 并非分类器已经把银色或黄铜色判错。
2. FPGA 白平衡的绿色通道直接通过，红、蓝通道乘以校正增益。没有一个本轮调大的绿色增益。红、蓝被不适当压低，也会造成相对偏绿。
3. 代码中确有一处遗漏：无效参考／配置失效会清除颜色校准状态，却可能保留原来的红、蓝补偿。新增仿真在修改前复现：旧增益均约 0.667 时，输入中性灰 RGB=(128,128,128)，输出变成 (85,128,85)。这是可导致偏绿的具体软件机制，但不能仅凭屏幕照片认定它是现场全部偏色的唯一原因。
4. 多目标版本没有修改 AWB 文件；当时变更集中在多目标遍历、结果关联和显示。用户观察到的版本间差异仍需在相同光照、设置、校准状态下比较，不能用这点否定现场反馈。

## 本轮改动

仅修改生产文件 `user_source/hdl_source/awb.v`：

- 解锁重校准、曝光／增益使校准失效时，丢弃旧统计和未完成的除法结果，复位目标增益。
- 参考被拒绝，或在未收敛／无效状态下锁定，不能继续保留旧补偿。无效锁定明确显示 BAD。
- 无效参考时在下一帧边界将红、蓝补偿置为 1 倍，避免残留增益人为放大偏色；像素数据延迟和输出有效节拍没有改变。
- 有效校准锁定后仍保持增益和参考，不会因放入其他颜色物体而重新学习。

曝光／增益启动值、形状判定、颜色比例门限、多目标算法、显示图标均未调整。1 倍补偿意味着输出去马赛克后的原始 RGB，不代表传感器与照明本身已经呈现中性色。真正修正现场色偏仍要完成有效校准。

## 先用现有 bit 做的操作

先保留 `EXP=2244`、`GAIN=112`，不要为了颜色压暗并破坏当前轮廓。

1. SW1～SW3 全关看 RGB，关闭 SW4。先移开中心区域的金属零件。
2. 不需要专用白卡。可用一张普通哑光白纸，平放在零件所在平面，覆盖画面中心一小片区域；参考窗口为 x=608～671、y=328～391。让参考纸接收与零件表面相同的照明，避免手的阴影、纸的边缘、金属、彩色物体进入窗口。
3. 等待 `WB:CAL REF:OK`，再打开 SW4，确认 `WB:LOCK REF:OK`，然后移开白纸，重新放入不同颜色的零件。
4. 拍一张包含状态行和全部零件标签的完整画面。若校准后仍偏绿，也照样保留现场并拍照。

可以先尝试直接用空白背光板校准，但前提是中心没有过曝、没有物体和阴影。当前采样拒绝原始任意通道高于 240、低于 64 或偏色过大的像素；一块看起来很亮的白板未必是有效参考。透射背光也不一定与金属反射照明具有相同光谱。

如果始终 `REF:BAD`，请保持 SW4 关闭，回传“空白背光板”和“中心白纸”两种完整画面，说明 EXP／GAIN 是否保持 2244／112；无需先降低它们。若状态 WAIT，表示参考已有但尚未收敛，以最终 OK 为准。`BAD` 本身不能区分过曝、欠曝与采样偏色，因此不应仅凭这一行继续盲调。

本轮代码修复要生效，需要用户自行在 `_osd_1/td_project/camera_to_dsi_display.al` 重新构建并下载 bit。没有运行 TD 综合、布局布线、bit 生成或烧录；请检查最终资源与 routed timing。

## 功能仿真

- 修改前新增用例确实失败，复现中性灰被旧增益染绿；见 `logs/tb_wb_invalid_before.log`，这是预期失败的缺陷证据。
- 修改后新增用例通过：拒绝参考后锁定、有效锁定保持、配置失效、解锁、在除法过程中失效、四像素输出的 1 倍回退；4096 个有效输出拍逐拍比对。
- 真实 AWB 对输入偏绿中性参考 (128,192,128) 的收敛测试通过，四个输出像素通道均落在 190～193；没有强制写入增益。
- 原中心参考校准、旧灰世界 AWB 与时序、25 组颜色比例测试通过。

仿真不包含真实摄像头光谱、屏幕拍摄色偏和现场反光；不能据此承诺照片中的所有颜色问题已经解决。修改前文件在 `before/`，本轮源文件快照在 `source/`，日志与清单在 `logs/`、`validation_summary.txt`。
