## 实际操作

1. 保持传送带停止，先让画面中心 64×64 区域露出正常背景，打开菜单选择 `AE:AUTO`。
2. 沿用原始绿色通道均值和 176～216 的宽死区。偏亮或偏暗连续四个有效观测包方向一致时才调整一次；每次 I2C 写入完成后先丢弃两个观测包，等待曝光生效。
3. 无已发布目标、相机配置完成、无待写参数时，连续八个观测包落在死区内才锁定，菜单显示 `AE:LOCK`。锁定后亮度变化、目标进入或传送带启停都不会再自动修改 EXP/GAIN。
4. 需要适应新的照明时，选择一次 `AE:MAN`，再切回 `AE:AUTO`，显式开始下一次调整。系统复位也清除锁定。手动修改菜单 EXP/GAIN 时沿用原逻辑转为 MAN。
5. 未收敛就启动传送带时显示 `AE:HOLD`，暂停自动调节；停带后可继续未完成的收敛。已经 LOCK 的会话停带后仍为 LOCK。

上电仍为原来的 MAN；不会擅自开始自动曝光。无法达到目标区间、达到 EXP/GAIN 上下限或亮度无效时不宣称 LOCK，不进行重复的相同参数 I2C 写入。亮度小于16仍沿用原逻辑不自动追亮，以免失效/遮挡数据驱动补偿。

这里的亮度是 `awb.v` 诊断包 `[119:112]` 的 AWB 前中心区域绿色均值，不是全图测光、物体测光或新的亮度算法。EXP 是该传感器现有控制码，不能直接当成微秒。自动白平衡没有随 AE 一起冻结；当前灯光/背板的颜色验证结论也不因本次修改而扩大。

## 为什么速度提高后会更难识别

源码与定向功能测试确认了一处明确限制：`img_parts_multi_tracker` 只在相邻**识别批次**的同类目标满足 `dx<=64 && dy<=64`、宽高变化各不超过32像素时继承确认历史；需三次关联观测才输出确认框。`tb_tracker_speed_boundary` 证明64像素/批次仍能确认，65像素/批次连续运动会反复从第一次确认开始。这里不是64像素/摄像头帧，不能在未知批次发布间隔、视野尺寸和实际带速时换算成毫米/秒。

同时，`img_tire.take` 在上一批尚未分析完成时会跳过新的帧头；现有 HDMI 插值只是让框移动平滑，不会提高前端识别频率，也不是速度预测跟踪。

## 帧差的作用与建议

帧差可以作为运动候选/活动区域证据，但不宜单独替换现有形状和颜色识别：对于相邻两帧在相同位置的像素，绝对差检测的是变化。停止或慢移物体的重合部分可能没有差分，移动织纹、阴影、曝光变化也可能产生差分。背景模型差分与相邻帧差分是不同方法；本工程已有的空带参考逻辑也不能直接称为已实现运动帧差。

建议后续结合现有 8×8 粗网格做低资源运动统计，以运动方向/估计速度辅助现有一对一目标关联，再根据稳定 ID 做越线计数；同时量测接受帧间隔、发布间隔和拖影。若要提高吞吐量，还要单独优化形态学/连通域分析和候选扫描。不能通过扩大一个位移门限或减少确认次数就宣称高速检测已可靠，也不能靠帧差恢复曝光造成的运动模糊。

本轮仅完成曝光锁定与速度限制的可复现分析，**未把帧差、速度预测或新的计数逻辑接入生产识别**；没有从另一个工程覆盖迁入算法。

参考资料：OpenCV 官方 `How to Use Background Subtraction Methods`（https://docs.opencv.org/4.x/d1/dc5/tutorial_background_subtraction.html）区分静态相机前景掩膜与背景模型更新；Basler 官方 `Exposure Auto`（https://docs.baslerweb.com/exposure-auto）中的 Once/Continuous 说明可用于理解一次性调节与连续调节的区别，不代表本工程传感器型号或控制寄存器相同。
