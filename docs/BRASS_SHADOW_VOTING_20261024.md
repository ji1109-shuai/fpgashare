# 暗黄铜螺钉颜色投票优化（2026-10-24）

## 现场判断

新照片中螺钉框选和 `SCREW` 形状标签稳定，颜色为 `UNKN`。白色背板在相机画面中已整体接近中性，而螺钉主体大面积处于暗影，只剩少量暖色反光。手机拍屏不能作为相机RGB真值，但现象与源码中的两级多数票限制一致：黄铜像素先要在每个8×8单元内超过已分类像素的一半，整件黄铜票又要达到有效颜色单元的40%。窄反光会在两级压缩中丢失。

自动白平衡仍采用全画面的候选中性像素，暗且偏色的螺钉大部分不进入参考统计；此前该版已在当前背光板和照明下解决整屏偏绿。因此本轮不改变 `awb.v`，避免为一件黄铜零件给白背景和银色件引入全局暖偏色。

## RTL修改

修改 `user_source/hdl_source/img_proj.v` 的零件颜色票决，不改变像素延迟、AWB、形状分割、DDR或显示路径。

1. 8×8单元内，黄铜证据至少8像素、占已分类像素至少25%，并且至少为红色证据的2倍时，允许黄铜优先于中性暗影/反光多数票。
2. 整件层，黄铜证据仍要求至少8个单元并相对红色2:1，但覆盖门限由40%改为25%。
3. 红色仍保留原40%门限；银色80%、黑色60%及有效样本覆盖、跨帧确认均不变。
4. 黄铜低于25%时不会阻断原黑色多数票，避免少量暖色环境反光把黑件误判为黄铜。

这仍是固定平台下的外观分类，不是材质光谱识别。若所有黄铜表面都变成无色黑/白，RGB信息已经丢失，数字逻辑无法恢复真实材质。

## 新增用例与功能仿真

`sim/tb_parts.v` 新增两组螺钉表面模型：

- 暗黄铜：只有3/8的8×8单元带黄铜反光；在这些单元中黄铜仅占1/4，其余为中性暗影，期望 `BRASS`。
- 黑件暖反光：每个单元仅1/8为暖色反光，其余为中性暗影，期望 `BLACK`。

使用 Vivado/XSim 2022.2 对最终规则运行：

- `tb_parts_color_hsv`：534组HSV/亮度/饱和度及两拍流水测试通过。
- `tb_parts_colours`：55帧银/黄铜/红/黑、反光阴影、混色拒绝和四种形状通过。
- `tb_parts_colour_stability`：校准门控、epoch、暗色、裁剪和内部回退通过。
- `tb_parts_multi_no_calibration`：21帧四目标、颜色确认、移除/换序、溢出、空场景及无手动校准通过。

## 上板复测

保持本次照片时的灯光、EXP/GAIN、相机高度和RGB显示模式，先单放这颗黄铜螺钉并等待至少两个识别批次。预期标签由 `UNKN` 稳定为 `BRASS`。随后在同一设置下放入黑色和银色零件，确认稀疏暖反光的黑件仍为 `BLACK`、银件仍为 `SILVER`。若黄铜仍为 `UNKN`，请拍清左侧 `RGB`、`R/S`、`Y/K`、`N/F` 和 `WHY`；下一步应依据真实票数调整，不再先改全局白平衡。
